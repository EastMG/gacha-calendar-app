# 设计规范

本文件记录**这个 App 的每个视觉数值从哪来**。原则：能追到官方文档的绝不凭感觉，
官方没规定的明确标注为工程决定。

- 三端原始调研材料：`_research/design/ref-apple.md`、`ref-google.md`、`ref-huawei.md`（含逐条出处链接）
- 落地实现：`apps/preview/src/design.ts`
- 规范符合性由 **`apps/preview/test/design.test.ts`（28 个断言）** 强制，不是靠"看着还行"

## 一、取源说明（为什么不能直接抄）

三家官方文档对爬虫都不友好，且**可信度差异很大**，必须先说清楚：

| 来源 | 可获取性 | 我们采用的通道 | 可信度标注 |
|---|---|---|---|
| Apple HIG | 页面 JS 渲染，直接抓只得到标题 | URL 后加 **`.md`** 可取官方 Markdown 源文 | ✅ HIG 原文 / 🟡 Apple 开发者文档 / ⛔ 未规定 |
| Material 3 | 全站 JS 渲染 | `r.jina.ai` 镜像取正文 + **Google 官方 token 仓库**（material-web `tokens/v0_192`、androidx Compose Material3 tokens）取精确 dp/sp | `[正文]` / `[Token]` / `[图示]` / `[未规定]` |
| HarmonyOS Design | SPA 空壳 | `r.jina.ai` 取原文 + `openharmony/docs` 的 ArkUI 原始 Markdown | A 官方规范 / A- 上架必选 / B ArkUI 默认值 / C 推断 |

> ⚠️ **重要发现：现行 Apple HIG 已把组件尺寸规格移出正文。**
> `layout`、`lists-and-tables`、`tab-bars`、`motion` 现在全是定性建议——
> **没有** iOS 边距、列表行高、tab bar 高度、圆角档位、动效时长。
> 这些只随 iOS 27 UI Kit（Figma/Sketch，需下载）下发。
> 所以凡属此类，本文一律标为**工程决定**，不冒充 Apple 规范。
>
> 另：流传甚广的「iOS 8pt 栅格」**不在 HIG 里**（HIG 唯一的网格规定是 tvOS 列网格）。
> Material 的间距基准也不是 4dp 而是 **8dp**（`space100`），4dp 只是 nested unit。

## 二、三家的核心数值

### 字号体系

| 角色 | iOS（pt，Dynamic Type Large 档） | Material 3（sp） | HarmonyOS（fp） |
|---|---|---|---|
| 大标题 | LargeTitle 34/41、Title1 28/34、Title2 **22/28** | headline-small 22/28/400 | Title_M 24 / Title_S 20 |
| 卡片标题 | **Headline 17/22/600** | **body-large 16/24/400**（强调用 500） | **Body_L 16** |
| 次要文本 | Subhead 15/20、Footnote 13/18 | body-medium 14/20、body-small 12/16 | Body_M 14 / Body_S 12 |
| 标签/徽标 | Caption2 **11/13（iOS 字号下限）** | label-small 11/16/500 | Caption_M **10** |
| 底部 Tab | 无官方数值 | label-medium **12/16/500** | **10vp** |

### 尺寸与间距

| 项 | iOS | Material 3 | HarmonyOS |
|---|---|---|---|
| 左右边距 | 16（工程值，HIG 未规定） | **16dp** | **16vp**（官方明文） |
| 卡片圆角 | 工程值 12 | **12dp**（唯一被正文写死的圆角） | **16vp**（列表内模块 8、按钮 20、半模态 32） |
| 卡片间距 | 工程值 8 | 工程值 8 | **12vp**（官方明文） |
| 主次文本间距 | — | — | **2vp**（官方明文，另两家无对应项） |
| 底部导航高 | 工程值 58（iOS 26 起为浮动玻璃条，无公开高度） | **64dp**（flexible，官方推荐；80dp baseline 已不推荐） | **48vp 平铺 / 56vp 悬浮胶囊** |
| 底部导航形态 | 全宽 + 材质模糊 | 全宽 + **56×32 active indicator** | **悬浮胶囊**，模糊背板上边缘 1px 分割线 |
| 触控目标 | **44×44pt**（绝对最小 28） | **≥48×48dp** | **≥48×48vp 推荐，不得 <40** |

### 色彩与暗色分层

| 项 | iOS | Material 3 | HarmonyOS |
|---|---|---|---|
| 分层机制 | 系统色 gray6/5/4 | **surface-container tonal**，tone 4→10→12→17→22 | **明度**（官方明文：深色下不靠投影） |
| 我们取的底/卡/内层 | `#000000` / `#1C1C1E` / `#2C2C2E` | `#0F1113` / `#1B1E23` / `#252A30` | `#000000` / `#17181A` / `#22242A` |
| 对比度要求 | 小字 **4.5:1**，暗色小字建议 7:1 | 沿用 WCAG AA | 正文 **>5:1**，且**不得 >17.6:1**（防刺眼） |

### 动效

| 来源 | 数值 |
|---|---|
| Material 3 | Emphasized **500ms** / decelerate 400 / accelerate 200；Standard 300/250/200；曲线 `cubic-bezier(0.2, 0, 0, 1)` |
| HarmonyOS | 颜色 100ms / 小范围 150ms / 列表项 200ms / 全屏 350ms；曲线 `cubic-bezier(0.40, 0, 0.20, 1.00)` |
| Apple | 现行 HIG 只给定性描述，**无时长数值** |

## 三、我们的决议：共享底座 + 三端皮肤

三家在**结构性规范**上高度一致，差异集中在四件事上。所以不写三套 UI：

**共享底座**（三家都一致，`SHARED`）
- 左右边距 16
- 触控目标 ≥48（覆盖 iOS 44 / M3 48 / 鸿蒙 48）
- 8px 间距栅格
- 分组列表 + 底部 4 个带文字的 tab
- 数字一律 tabular

**皮肤差异**（`PLATFORMS`，逐项可测）

| 差异项 | iOS | Material 3 | 鸿蒙 |
|---|---|---|---|
| 卡片标题 | 17 / 600 | 16 / 500 | 16 / 500 |
| 次要文本 | 13 | 12 | 12 |
| 倒计时 | 15 / 600 | 14 / 500 | 14 / 500 |
| tab 文字 | 10 | 12 | 10 |
| 卡片圆角 | 12 | 12 | **16** |
| 卡片间距 | 8 | 8 | **12** |
| 底部导航 | 58 全宽 + 模糊 | **64** 全宽 + 56×32 indicator | **56 悬浮胶囊**（内缩 12、圆角 20） |
| 图标按钮 | 44 | 48 | 48 |

预览里点顶栏右侧的平台按钮（或在「数据」页的「界面规范」里选）可以实时切换对比。
**真实 App 会跟随系统自动选择，不是让用户手选。**

## 四、把官方阈值变成断言

`apps/preview/test/design.test.ts` 把规范写死为测试，改配色时不会悄悄跌破：

| 断言 | 阈值 | 依据 |
|---|---|---|
| 正文 vs 卡片 | ≥ 7:1 且 **≤ 17.6:1** | Apple 暗色小字建议 7:1；鸿蒙正文 >5:1 且上限 17.6:1 |
| 次要文本 | ≥ 5:1 | 鸿蒙正文 >5:1 |
| 三级文本 / 语义色 / 强调色 | ≥ 4.5:1 | Apple 小字 4.5:1 |
| 层级单调 | surface < card < cardAlt，且相邻对比 > 1.15 | 鸿蒙"用明度表达层级" |
| 触控目标 | iOS ≥44、M3/鸿蒙 ≥48 | 三家明文 |
| 图标按钮直径 | ≥ 触控目标 | 否则点不到 |
| 字号下限 | iOS ≥11、鸿蒙 ≥10 | Caption2 / Caption_M |
| 倒计时字号 | ≤ 卡片标题字号 | M3：不为塞内容改字号，靠字重强调 |

## 五、修复掉的规范问题

上一版对照三家规范，实测出的违规（已修）：

| 问题 | 改前 | 改后 | 依据 |
|---|---|---|---|
| 触控目标不足 | 刷新按钮 34×34 | 44 / 48 / 48 | iOS 44pt、M3 48dp |
| 边距不足 | 12px | 16px | 三家一致 16 |
| 正文过小 | 14px | 16–17px | iOS Body 17、M3 body-large 16 |
| 倒计时抖动 | 比例数字，逐秒 reflow | `tabular-nums` + 定宽容器 | Apple：SF Pro 默认比例数字 |
| 暗色次要信息对比度可能 <4.5 | 未校验 | 全部 ≥5:1，实测断言 | Apple 4.5:1、鸿蒙 >5:1 |
| 层级靠颜色差异硬凑 | — | surface/card/cardAlt 亮度单调递增 | 鸿蒙明度分层 |

## 六、明确标注"官方没规定"的项

以下是我们**自己的工程决定**，不要当成某家规范：

- 列表行的标准/最小高度（三家均未给；鸿蒙"列表"设计页确认无数值）
- 倒计时的"定宽容器"防抖（Apple 只给了 `monospacedDigit()` API，没规定布局做法）
- 数字等宽 `tabular-nums`（**Material 3 完全没有数字宽度规范**，token 体系里没有对应项）
- 分段标题 sticky（M3 无 sticky header 组件）
- 日历/时间线布局（M3 canonical layouts 里没有）
- iOS tab bar 高度、列表行高、inset grouped 缩进、分隔线粗细
- 卡片内边距（鸿蒙只给了卡片之间 12vp，没给内部 padding）
- 中文字重映射（PingFang / HarmonyOS Sans / 思源黑体的字重命名不统一）
- 按钮高度 40vp（业界常引用，但未取到华为官方原文）

## 七、尚未做的

- **动态字体 / 无障碍缩放**：iOS Dynamic Type 与鸿蒙 fp 都会随系统字号缩放，当前是固定 px。真机上必须改
