# 上架合规：抓第三方游戏数据的风险与规避

这个 App 的数据来自各游戏官网公开公告与公开 wiki，**不涉及破解、不涉及账号**。
但这不代表没有风险 —— 风险主要来自"品牌资产"与"冒充官方"，而不是"抓公开公告"本身。

## 已有判例（最硬的一手证据）

**米哈游诉"游创工坊"案**：被告未经授权长期使用《原神》官方美术素材、运营"抽卡数据分析工具"、
套用米游社登录界面诱导玩家提供游戏数据。法院受理不正当竞争 + 著作权侵权，
并作出**诉中禁令**，要求立即停止侵权、**不得重新上架**相关功能。

**结论**：这类 App 的真实雷区是——

1. 用官方美术素材（logo / 立绘 / UI 截图）
2. 冒充官方或暗示授权
3. 诱导玩家交出账号数据

**三条任意踩一条都会招来下架或诉讼。** 只抓公开公告的排期时间，风险等级完全不同。

## 三个商店的规则要点

| 商店 | 相关条款 | 对本项目的含义 |
|---|---|---|
| **App Store** | 5.2.2 第三方内容需授权且不得暗示官方背书；4.2 最低功能（不能只是网页抓取的壳） | 必须有**自己的编辑加工**：排期整理、提醒、筛选、跨游对比。不能把 28 个官网页面拼起来 |
| **Google Play** | Deceptive Behavior / 知识产权 | 名称图标描述须与官方区分；需隐私政策与 Data safety 声明 |
| **华为应用市场** | 高频拒因：隐私政策需独立 HTTPS 链接 + 首启弹窗；权限逐条说明；**后台不得"sleep 后还在抓数据"**；应用名不得含"华为官方"；release 包不得留 `console.log`；包体 < 200MB；**冷启动 < 2 秒**；网络异常必须有 UI 兜底 | 后台刷新改为"系统提醒 + 前台增量刷新"；"数据健康"页正好满足"网络异常有兜底" |

## 本项目的规避清单（写进产品规范）

1. **不碰品牌资产。** 不用任何游戏 logo、角色立绘、官方 UI 截图。
   图标 / 配图自制或纯文字排版。（当前预览刻意不加载游戏图标，就是为了不引入外链素材。）
2. **只聚合事实性信息。** 起止时间、活动名称、版本号 —— 这类事实性数据版权保护弱。
   **不转载公告全文**、不搬运攻略、不复制官方文案；需要描述时用自己的话，并附原文链接。
3. **不做账号 / 充值 / 抽卡记录。** 不要求登录、不收集 authkey、不接入任何游戏 API。
   这一条直接避开判例里最致命的行为。
4. **不做"官方"暗示。** 关于页写明"非官方应用，数据来自各游戏官网公开公告，版权归原权利方"；
   提供权利人下架请求通道（issue / 邮箱），收到即删 —— 这是审核最认的"善意"证据。
5. **数据来源可追溯。** 每条记录尽量带来源与抓取时间；
   `selfCheck()` 结果做成"数据健康"页（预览里已有雏形）。
6. **避免抽卡概率诱导。** 不做概率计算工具（概率公示是游戏公司义务，
   第三方做易被认定误导），不用"必出""欧皇"之类文案。
7. **上架顺序**：先 **华为应用市场**（对这类工具相对宽容）→ **Google Play**（海外）→
   **App Store**（最严，留到最后，且准备好"编辑加工"的证据）。

## 与上游的关系

抓取规则与数据来源定义在 [`dsh-gacha-calendar`](https://github.com/EastMG/dsh-gacha-calendar)。
若某个源站提出异议，处理方式是**在上游删掉该来源**，本仓库不需要改代码
（`listGames()` 会自动少一条）—— 这也是"不复制抓取逻辑"的额外收益。
